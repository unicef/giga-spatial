# Share an internal view generator base and a uniform enrichment contract

Status: Accepted — rolled out in three steps (see `.scratch/view-generator-unification/`).

`PoiViewGenerator` and the zonal view generators (`ZonalViewGenerator`, `AdminBoundariesViewGenerator`, `H3ViewGenerator`, `S2ViewGenerator`, and `MercatorViewGenerator`) share an internal base class, `BaseViewGenerator` in `gigaspatial/generators/_base.py`, while `GeometryBasedZonalViewGenerator` collapses into `ZonalViewGenerator` and remains only as a deprecated alias. Every generator holds its enriched view as a geometry-free `DataFrame` keyed by a canonical `id_column` (`"poi_id"` for points of interest, `"zone_id"` for zones); `.to_geodataframe()` re-attaches geometries in the generator's CRS, and `.save_view(path)` takes a target path directly and delegates format dispatch to `write_dataset`. Every `map_*` method (both low-level spatial primitives `map_points`, `map_polygons`, `map_rasters`, `map_nearest_points`, `map_zonal_stats` and dataset enrichment methods) updates `self._view` and returns `self.view`, raises `ValueError` if an output column already exists unless `overwrite=True`, propagates handler resolution or availability failures as exceptions, and fills target columns with semantic empty values (`0` for counts, `False` for boolean flags, `np.nan` for continuous or categorical statistics) when a loaded dataset contains zero intersecting features.

## Considered options

- **Keep `PoiViewGenerator` and `ZonalViewGenerator` independent.** Rejected: both duplicated view state management, `save_view`, `to_dataframe`, `to_geodataframe`, `_ensure_tif_list`, and the WorldPop and GHSL mapping pipelines (~350 lines), causing parameter names (`dataset_year` vs `year`) and empty-data return values (`GeoDataFrame`, `None`, or un-updated `self.view`) to drift.
- **Keep the two-layer `ZonalViewGenerator` + `GeometryBasedZonalViewGenerator` split and per-grid `map_*` overrides.** Rejected: `GeometryBasedZonalViewGenerator` was the sole subclass of `ZonalViewGenerator`, and `AdminBoundariesViewGenerator`, `H3ViewGenerator`, `S2ViewGenerator`, and `MercatorViewGenerator` each repeated 38 lines of pass-through overrides just to default `country = self._country`.
- **Preserve caller-supplied ID column names in `self.view` instead of renaming to `id_column`.** Rejected: built-in zonal generators source their IDs from `"h3"`, `"cell_token"`, `"quadkey"`, and `"boundary_id"`. Standardising to `"poi_id"` and `"zone_id"` guarantees a predictable key column across every view, while raising `ValueError` if a custom `poi_id_column` or `zone_id_column` is missing from the input or collides with an existing `"poi_id"` / `"zone_id"` column.
- **Silently overwrite existing columns or leave low-level `map_*` methods stateless.** Rejected: default output column names (such as `"population"` or `"built_surface_m2"`) caused chained calls with different radii or cohorts to clobber earlier results unless `overwrite=False` raises by default, and stateless `map_points` / `map_zonal_stats` forced callers into awkward two-step `add_variable_to_view(map_points(...))` patterns that broke on multi-column aggregations.
- **Keep `PoiViewGeneratorConfig` and `ZonalViewGeneratorConfig` as the primary way to configure `save_view` paths and formats.** Rejected: `write_dataset` already dispatches on file extensions, so `save_view(path)` taking a path directly and `ensure_available: bool = True` living on the generator constructor makes the config classes unnecessary indirection; they are deprecated.

## Consequences

- `BaseViewGenerator` is an internal module ([ADR 0002](0002-handler-base-in-the-api-reference.md), [ADR 0003](0003-public-import-paths.md)), not exported at the top level. `ZonalViewGenerator` is exported at `gigaspatial`, `gigaspatial.generators`, and `gigaspatial.generators.zonal`; instantiating `GeometryBasedZonalViewGenerator` or passing `PoiViewGeneratorConfig` / `ZonalViewGeneratorConfig` emits a `DeprecationWarning`.
- Dataset enrichment methods shared across points of interest and zones (`map_wp_pop`, `map_ghsl`, `map_built_s`, `map_smod`, `map_ghsl_pop`, `map_rwi`, `map_aqueduct_flood_hazard`) live on `BaseViewGenerator` and accept an optional `handler=None` argument so tests can inject local-substitutable handlers backed by `LocalDataStore` fixtures without network calls.
- Building footprint methods stay on their respective subclasses because their domain operations differ: `PoiViewGenerator` finds nearest building footprints (`find_nearest_buildings`, `map_google_buildings`, `map_ms_buildings`), whereas `ZonalViewGenerator` performs zonal aggregation of building counts and areas (`map_buildings`, `map_google_buildings`, `map_ms_buildings`).
- Public return-type changes (`ZonalViewGenerator.map_points`, `map_polygons`, and `map_rasters` returning `self.view` instead of `Dict`; `PoiViewGenerator.map_zonal_stats` and `map_nearest_points` updating and returning `self.view`; empty dataset results returning `self.view` with `0`/`False`/`NaN`-filled columns instead of a raw `GeoDataFrame` or `None`) and the bug fix for custom `poi_id_column` validation must be listed in `CHANGELOG.md`.
