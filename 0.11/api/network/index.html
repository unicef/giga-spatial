    Spatial networks¶

    A SpatialNetwork holds places as nodes with coordinates, joined by edges with a length in meters or another weight. A road network from OSMRoadsFetcher is one kind. The network is two tables, and every edit returns a new network. The road networks guide shows a full workflow.

    from gigaspatial import SpatialNetwork, OSMRoadsFetcher

    to_pandana and backend="pandana" need pip install "giga-spatial[pandana]". Why the network is held as tables, and how a saved network is laid out, are in ADR 0004 and ADR 0005.

    The methods below are in this order: building, saving, and converting; reading the tables; editing; inserting points; algorithms; and reducing.

    Bases: EditingMixin, AlgorithmsMixin, ReductionMixin, InsertionMixin

    A spatial network held as a nodes table and an edges table.

    Nodes carry coordinates in EPSG:4326, and edges carry a length in meters or another weight. A road network fetched by OSMRoadsFetcher is one kind; points joined to their nearest neighbours are another.

    The nodes table is indexed by node_id and has the columns x (longitude), y (latitude), and kind, plus any attributes. The edges table has u, v, key, length (meters), kind, an optional geometry column of LineStrings, and any attributes. An edge is identified by (u, v, key).

    A network never changes after it is built: methods that edit it return a new network. The tables returned by nodes and edges are shallow copies; adding columns to them does not change the network, but do not modify their values in place.

    insert_points(points, id_column=None, max_distance=None, snap_to_node=5.0, chain=False, return_skipped=False) ¶

    Insert points of interest as nodes, each joined to its nearest road.

    Each point is joined to the nearest road edge at the foot of the perpendicular: the edge is split there, a node of kind split is added, and a connection edge joins the point (kind point) to it. When the foot is within snap_to_node meters of the edge's end, the point connects to that node instead. Points whose feet fall on the same spot share one split node. Each road edge is split once, at all of its points, and the pieces' lengths add up exactly to the original length. In a directed network, both directions of a two-way road are split at the same nodes, and connections run both ways.

    Parameters:

    Name Type Description Default
    points Any

    A GeoDataFrame of points, a DataFrame with latitude and longitude columns, or a list of (lat, lon) tuples. Their other columns become node attributes.

    		 required
    id_column Optional[str]

    Column holding the point IDs. The frame's index otherwise.

    		 None
    max_distance Optional[float]

    Meters. Points farther from any road are skipped, with a warning.

    		 None
    snap_to_node float

    		 5.0

    simplify(keep=None, sum_columns=('length',)) ¶

    Remove nodes that only continue a road, joining the edges on either side.

    A node is removed when it has exactly two neighbours and its edges continue through it: one edge in and one out of a one-way road, or both directions of a two-way road (in an undirected network, exactly two edges). This is the rule osmnx uses, except that osmnx also removes nodes between duplicated parallel ways and drops one of the ways, and deletes rings with no junction at all; here those nodes stay, and a ring keeps one node. Nodes of kind point or split and nodes in keep are never removed.

    Joined edges get:

    • the sum of sum_columns and of the network's weight column;
    • one geometry along the joined edges;
    • text joined with ; where values differ, without repeats;
    • osmid and other list columns concatenated, without repeats;
    • oneway true only if every part is one-way, reversed true if any part is, other booleans true only if all parts are;
    • the length-weighted mean of other numeric columns;
    • the kind of their longest part.

    Each direction of a two-way road is joined separately, so it stays two-way when both directions can be joined. Joined edges always get a geometry, as in osmnx, so a network without edge geometry gains a geometry column that is missing for the edges left as they were.

    Connection planning¶

    ConnectionPlanner plans how to connect terminals, such as schools, to roots, such as fibre nodes, along a network at the smallest shared cost, and returns a ConnectionPlan. Why it is a rooted Steiner tree and a separate object is in ADR 0008.

    from gigaspatial import ConnectionPlanner

plan = ConnectionPlanner(network, school_ids, roots=fibre_ids, weight="cost").plan()

    Plans how to connect terminals to roots along a spatial network at the smallest shared cost.

    Terminals are the points to connect, such as schools. Roots are nodes already connected to each other through an existing network, such as fibre nodes, a power grid's substations, or water mains; reaching any root is enough. A terminal may reach a root directly or through other terminals, and an edge used by several terminals is paid once. Directions are ignored, since a cable or a pipe does not follow one-way streets.

    With roots, this is the Steiner tree problem once every root is joined to one virtual root at weight 0: the plan is a forest whose every tree reaches a root. Without roots, it is the Steiner tree joining the terminals. Both are NP-hard; the planner returns approximations.

    Insert the terminals and roots into the network first, with :meth:SpatialNetwork.insert_points, and pass their node IDs.

    plan(method='shortest_path') ¶

    Plan the connections.

    Parameters:

    Name Type Description Default
    method str

    "shortest_path" (the default): Takahashi and Matsuyama's 2-approximation of the Steiner tree, and a model of a phased rollout: starting from the roots (or the first terminal), repeatedly connect the terminal nearest to anything connected so far, along its shortest path. Gives each terminal's order and marginal cost; ties go to the terminal listed first. On Kigali's roads it came within 0.7 to 6% of the optimum. "steiner": Mehlhorn's 2-approximation, with roots the rooted tree, without them the tree joining the terminals; 5 to 20 times faster, and 3 to 9% above the optimum on Kigali. :meth:improve brings either within about 1% of it. "nearest_root": each terminal's shortest path to its nearest root, and the union of those paths; needs roots, and never lets a terminal connect through another one. "all_pairs": the shortest paths between every terminal and every terminal or root; their number grows with the square of the terminals.

    		 'shortest_path'
