    Handler base¶

    This section is for adding a dataset to this library. The classes below are internal: this repository is their only subclasser, and the hooks are not a stable API for other packages. Documenting them does not change that. See the decision.

    The guides never use these names. A caller passes a source and may set crop_to_source. The classes live in gigaspatial.handlers.base, which is not a public import path.

    Search key and search geometry¶

    A handler turns a source into files in two different ways.

    The search key is what the dataset's index understands. It may be a country code, a filter, a geometry, or nothing, for a dataset published as one global file. get_search_key is the method a dataset overrides.

    The search geometry is always a Shapely geometry in the handler's CRS. Cropping uses only that geometry. extract_search_geometry builds it. A search key that is a geometry is the search geometry.

    The split, and the cases where a country source is not cropped, are recorded in Search key and search geometry.

    Anything that changes which file is fetched belongs on the data unit, not in an option the downloader has to interpret.

    The classes¶

    BaseHandler is what a caller holds. load_data ensures the files are stored, then reads them. BaseHandlerConfig resolves a source into data units and stored paths. BaseHandlerDownloader fetches units. BaseHandlerReader loads stored paths and may crop.

    Keyword arguments stop at those public methods. Each class declares an options type: ResolveOptions, DownloadOptions, or ReadOptions. An unknown keyword raises TypeError.

    Bases: ABC

    Abstract base class for handler configurations.

    Standardizes common fields used across all handlers, such as file paths, worker counts, and data store abstractions.

    A source is resolved in two steps. get_search_key turns it into the value the dataset's own lookup understands (by default the search geometry), and get_relevant_data_units_by_key turns that key into data units. The search geometry, the area used for cropping, is always built by extract_search_geometry in crs.

    Attributes:

    Name Type Description
    base_path Path

    Root directory for the dataset's files.
    n_workers int

    Number of threads downloading data units at once.
    data_store DataStore

    Abstraction for file-system access (local or cloud).
    logger Logger

    Logger instance for tracking handler operations.
    units_match_country bool

    True when the dataset is published per country, so data loaded for a country source already covers exactly that country and is not cropped.
    options_type Type[ResolveOptions]

    The ResolveOptions subclass this config's hooks take.

    extract_search_geometry(source, options=None) ¶

    Build the search geometry of a source, in self.crs.

    The input coordinates are read in the GeoDataFrame's own CRS, else in the crs option, else in EPSG:4326, and reprojected to self.crs. Country sources use the country's admin boundary.
